## 3️⃣ จุดเสี่ยง / จุดยากทางเทคนิค

### 🔴 จุดตาย #1: ตัดสต็อก (ยากที่สุด!)

```
ทำไมยาก:
  เมื่อกด "ยืนยันจัดส่ง" → ระบบตัดสต็อกอัตโนมัติทันที
  ถ้า 2 คนกดพร้อมกัน → สต็อกอาจตัดซ้ำ → ข้อมูลผิด!

ตัวอย่าง:
  สต็อกมี 100 ชิ้น
  คน A กดส่ง 80 ชิ้น  ──┐
  คน B กดส่ง 80 ชิ้น  ──┤── ถ้าไม่ Lock → ตัดได้ทั้งคู่ = -60 ชิ้น!
                          └── ติดลบ = พัง!

วิธีแก้ (ที่วางแผนไว้):
  ✅ ใช้ DB Transaction → ถ้าพัง → Rollback ทั้งหมด (ไม่มีตัดครึ่งๆ)
  ✅ ใช้ Row Lock → คนที่ 2 ต้องรอคนแรกเสร็จก่อน
  ✅ เช็คสต็อกก่อนตัด → ถ้าไม่พอ → แจ้ง Error ทันที
```

### 🔴 จุดตาย #2: เลขเอกสารซ้ำ

```
ทำไมยาก:
  เอกสาร QU-2026-0001, QU-2026-0002...
  ถ้า 2 คนสร้างพร้อมกัน → อาจได้เลขเดียวกัน!

วิธีแก้:
  ✅ ใช้ Row Lock ตอนหาเลขล่าสุด → ป้องกันซ้ำ
  ✅ ใส่ UNIQUE constraint ใน Database → ซ้ำไม่ได้เด็ดขาด
```

### 🟡 จุดยาก #3: สกุลเงิน USD/THB

```
ทำไมต้องระวัง:
  ฝั่ง Supplier = USD ($3.50/ชิ้น)
  ฝั่งลูกค้า = THB (฿150/ชิ้น)

  ⚠️ ราคาเดียวกัน แต่คนละสกุลเงิน!
  ⚠️ ต้องไม่สับสนว่า field ไหนเป็น USD field ไหนเป็น THB

วิธีแก้:
  ✅ แยกชัดเจน — Supplier Bills มี currency field (USD)
  ✅ Finance Documents ไม่มี currency field (THB เท่านั้น)
  ✅ ไม่ต้องแปลงสกุลเงินในระบบ (คำนวณ margin เอานอกระบบ)
```

### 🟡 จุดยาก #4: Partial Delivery (ส่งแบ่งรอบ)

```
ทำไมยาก:
  สั่ง 10,000 ชิ้น → แต่ส่ง 3 รอบ:
    รอบ 1: 4,000 ชิ้น → ตัดสต็อก 4,000
    รอบ 2: 3,000 ชิ้น → ตัดสต็อก 3,000
    รอบ 3: 3,000 ชิ้น → ตัดสต็อก 3,000

  ต้องติดตามว่าส่งไปแล้วเท่าไหร่ เหลืออีกเท่าไหร่
  ถ้า SUM ผิด → ส่งเกิน/ส่งขาด

วิธีแก้:
  ✅ ทุก Dispatch Round ผูกกับ Project + สินค้า
  ✅ ตัดสต็อกทีละรอบ (ไม่ใช่ตัดทีเดียว)
  ✅ เช็ค SUM ก่อนยืนยัน → ถ้าเกินจำนวนสั่ง → แจ้ง Error
```
